# Security reporting

safeclone 0.1.0 is experimental. Read the [security model](docs/security-model.md)
and [supported environment](docs/support.md) before using it. Detection and
verification do not establish that a workspace is safe to disclose.

Do not disclose security vulnerabilities in public issues. The published
GitHub repository will use **GitHub Private Vulnerability Reporting**. Once
enabled, the repository's **Security** section will be the authoritative
entry point for private reports.

The public repository has not been created yet, so this reporting mechanism
is not currently available. Its availability must be verified in the
repository before the reporting instructions describe it as enabled.

Do not put secrets, original/private workspaces, sensitive paths, private session
artifacts or confidential exploit details in public issues or logs. Keep any
reproduction synthetic and avoid including the affected data itself.
